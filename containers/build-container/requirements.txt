# Python environment of the MCUHome builder image (containers/builder/).
#
# Fully pinned, including transitive dependencies: the image is the one
# build environment (ADR 0007), so "same image tag" has to mean "same
# packages" — a floating dependency would make two builds of the same
# image tag differ. Regenerate with `pip freeze` inside the image after
# changing the direct dependencies below, and bump the image revision in
# mcuhome/container.py in the same commit.
#
# Direct dependencies and why they are here:
#
#   west                      the Zephyr build front end, and `west twister`
#   pyelftools, intelhex      Zephyr image post-processing
#   anytree                   Zephyr rom/ram_report — the memory report
#   PyYAML, pykwalify         Zephyr's YAML handling (bindings, twister)
#   jsonschema                west manifest / zephyr_module validation
#   packaging, semver         version comparisons in Zephyr's CMake glue
#   canopen, pylink-square,   west's built-in flash/debug runners import
#     pyserial, patool,       these at load time; without them `west build`
#     psutil, requests, tqdm  prints import warnings on every invocation
#   colorama, ply, natsort,   twister
#     tabulate, junitparser,
#     python-dotenv, pytest
#   click, coloredlogs,       CHIP's codegen — scripts/setup/
#     jinja2, lark              requirements.build.txt, imported by
#                               scripts/codegen_paths.py during the Matter
#                               data-model generation of every build
#   cbor, cbor2               the rest of CHIP's
#                               scripts/setup/requirements.zephyr.txt
#   cryptography              MCUboot's imgtool
#                               (bootloader/mcuboot/scripts/requirements.txt
#                               pins cryptography>=40.0.0). Needed by EVERY
#                               build, not only a signing one: sysbuild runs
#                               `imgtool getpub` to generate the bootloader's
#                               autogen-pubkey.c, and imgtool imports
#                               cryptography at module load. Without it a
#                               container build dies at the MCUboot image
#                               even with --no-sign, which is why the
#                               container path had never produced a Matter
#                               image before 2026-08-09 — every signed
#                               artifact so far came from the host method,
#                               where the host interpreter supplies it.
#   ruamel.yaml               the MCUHome builder package itself
#
# CHIP's build requirements also list `python-path`. It is deliberately
# absent: scripts/pyshim/ stands in for it and goes first on PYTHONPATH
# (upstream candidate C1), and the container must not quietly behave
# differently from a local-dev build there.
#
# Deliberately NOT here: pyocd, opencv-python, numpy, spdx-tools
# (Zephyr's requirements-run-test.txt) — hardware runners and reporting
# the image has no use for, and several hundred megabytes. python-can is
# present only because canopen depends on it.
